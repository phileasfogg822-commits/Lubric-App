# Release signing for the field app

The field APK is **signed by one permanent key**. This is not optional: Android
refuses to install an update whose signing certificate differs from the
installed app's, so if this key is lost or rotated, every phone must be
uninstalled by hand — which wipes the local database and the pairing, and the
device has to be set up from scratch. Keep it safe.

## Where the key lives

| Copy | Where | Notes |
|---|---|---|
| Canonical | `/root/lubric-keys/lubric_release.jks` on the VPS (72.61.115.120), `chmod 600` | root-only, outside the served app directory |
| CI | GitHub Actions secret `LUBRIC_KEYSTORE_BASE64` (base64 of the same file) | what actually signs the builds |
| Local | `%USERPROFILE%\.ssh\lubric_release.jks` | working copy |

Password and alias are the same on every copy:

```
storePassword = keyPassword = lubric-field-2026-release
keyAlias      = lubric
```

The certificate that every release must carry:

```
SHA256: B0:C8:2C:73:2B:EF:FF:A2:7C:B8:B3:D4:3A:CF:86:EC:78:96:7D:6F:72:34:BE:7F:8A:2C:FA:91:D5:96:82:CE
```

That fingerprint is stored as the GitHub **variable** `LUBRIC_KEY_FINGERPRINT`,
and the release workflow fails the build if the signed APK does not match it.

## To recover the key

```bash
scp -i ~/.ssh/lubric9_deploy2 root@72.61.115.120:/root/lubric-keys/lubric_release.jks .
keytool -list -v -keystore lubric_release.jks -storepass lubric-field-2026-release
```

If the VPS copy is gone, the GitHub secret is still authoritative:
`gh secret get LUBRIC_KEYSTORE_BASE64 --repo hrperalglobalcity-spec/lubric-field | base64 -d > lubric_release.jks`

**If both are gone, there is no way back** — generate a new key, but every
phone must be uninstalled and re-paired once. Treat it as unrecoverable.

## How the build uses it

`Restore the release signing key` writes `field_app/android/key.properties`
before `flutter build apk --release`, which picks it up automatically. The
`android/` directory is generated by CI and is not committed.

## Why this exists

Every build up to and including 0.4.0 was signed with the **debug key the CI
runner generates fresh on each job**, so all four published APKs carried four
different certificates. Any update attempt failed with "App not installed",
which is why each release had to be side-loaded by hand and the phone had to be
wiped and re-paired. This is the signing half of the fix; the other half was the
version comparison in `lib/core/update.dart`, which derived the installed
versionCode from the version *name* ("0.4.0" → 40) and so could never offer an
update.
