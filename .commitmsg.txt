Fix phone sync: the outbox encoder never quoted string values

Root cause of every failed field upload. Db._encode built JSON by hand:

    parts.add('"${_escape(k)}":$value')

The KEY was quoted, the VALUE was not. So a movement was stored as

    {"uuid":e820ccc8-c513-4479-a6ff-a333485b0789,"kind":collection,...
             ^ character 9

jsonDecode threw FormatException at character 9 - the first string field - the
push aborted, the outbox never drained, and every retry failed identically. No
collection taken on a phone had ever reached the shop, while the server looked
healthy because it was.

The encoder's comment claimed it "avoids pulling a JSON package into the app",
but dart:convert ships with the SDK and sync.dart already imported it. It
bought nothing and cost every sync.

- Payloads now live in outbox_payload.dart as pure functions returning maps,
  encoded with jsonEncode. Pure means unit-testable with no device - the gap
  that let this ship. Every earlier test hand-wrote proper JSON, so the phone's
  own encoder was never exercised end to end.
- Rows already stuck are rebuilt from the local table on the v1 to v2 upgrade,
  so field collections upload instead of having to be re-entered. Anything
  unrecoverable moves to sync_failures rather than vanishing.
- openDatabase had no onUpgrade at all; any future schema change would have
  silently stranded data on every installed phone. Now version 2 with a
  re-runnable migration.
- markRejected deleted the row and recorded nothing, so a refused collection
  disappeared with only a count to show for it. It now lands in
  sync_failures with the server's reason, listed in More with Retry/Discard.

Separately, the updater could not install: Android 8+ refuses the install
intent without REQUEST_INSTALL_PACKAGES, and refuses it silently - download
finishes, nothing happens, no error. patch_android.py now adds it and CI fails
the build if it is missing. No FileProvider was added: open_filex already ships
one whose filepaths.xml covers every directory we download to. The APK now goes
to an external updates/ dir and the dialog shows the path, because it used to
land in the private cache where nothing could find it.

Tests, all reading one shared golden fixture so the two halves of the protocol
cannot drift again:
- field_app/test/outbox_payload_test.dart: encode/decode round trips, the exact
  broken byte sequence, the old payload failing to parse, hostile
  (quote/backslash/newline/Urdu/emoji) text, and rebuild-from-local-row.
- server/e2e_payload.js: pushes the SAME fixture to the live shop, asserts both
  shapes land with values intact, plus an idempotent retry. 8/8 against prod.

Bumps the field app to 0.6.1+7.
