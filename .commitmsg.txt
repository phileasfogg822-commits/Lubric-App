Make field collections visible in the shop

The phones were uploading correctly all along. Collections were sitting in
Postgres - including the row whose uuid appeared in the FormatException report,
rescued by the 0.6.1 migration - and the shop still could not see them,
because `cash_movements` and `reservations` were the only tables in the entire
system that no screen read. Grep found them in exactly one place: the desktop
sync table list. From the counter that is indistinguishable from a broken sync.

- New Field Activity page (nav + /field, gated on `dashboard` because a
  collector holding cash must be visible to anyone who can see the dashboard):
  collected / handed over / still-in-hand totals, per-record rows with the
  sending phone, date filters, CSV export, plus a reservations table.
- Dashboard card summarising the last 7 days with a link to the page.
- Migration 019: `customer_name` on both tables. The field app records WHO was
  collected from, and /api/v1/push filters incoming rows down to real columns -
  so customer_name was discarded on every single upload, silently. Verified
  against prod: it now persists, quotes and ampersands intact.
- Migration 019 also stamps `taken_by_device_id` from the authenticated device
  in the push handler. The phone cannot know its own id, and the request is
  already authenticated as that device, so this is the only attribution that
  cannot be spoofed. ON DELETE SET NULL so removing a phone is never blocked.
- Indexes on (shop_id, occurred_at DESC) for the range queries.
- localDb.ts never created cash_movements or reservations even though the sync
  agent replicates both, so offline mode would have failed with "no such table"
  on the first pull. Added as LOCAL_SCHEMA_4, mirroring the server columns.

The three existing rows show a blank customer and phone: they were uploaded
before this change, so that detail was already gone and cannot be recovered.
Every new collection carries both.

Verified: 8/8 payload and 19/19 pairing checks against prod, and the page's
own queries return the 3 real collections (PKR 27,500 collected, 0 handed
over - so 27,500 is currently in hand with the phones).
